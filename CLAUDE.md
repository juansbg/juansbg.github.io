# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**The Family** — a narrator assistant for a social-deduction party game in the Werewolf/Mafia family. It is a tool for the single person running the game, not for the players. It tracks who has which role, walks the narrator through the night step by step in script order, resolves kills and protections, and prints a morning report.

The game was called **Omertà** until 2026-09-11; user testing found the name obscure and forgettable, and a sweep of the app stores, the board game listings and the trade mark registers ruled out Alibi (a same-named pass-and-play social deduction app), Vendetta ("Mafia: Vendetta") and Silencio (a Zoch card game) before The Family came through clean. It is one brand for both languages, and the crew is already "the Family" / "la Familia" in play. `APP_NAME` in `src/i18n/strings.ts` is the one place the name is written for the app: both tables' `appName` and `ui.tv.title` read it, and the setup wordmark, the paper's mastheads and the share file derive from it; the manifest (`vite.config.ts`) and the three page titles carry the same words by hand. The `omerta:*` storage keys and the `omerta-relay` worker keep their names on purpose: invisible to players, and a rename would cost every installed phone its saved game and the relay its address.

The game is themed around **organised crime**, with a light occult streak on two roles. It began as a Spanish werewolf game (*Pueblo Duerme*, still live in `legacy/`) and was re-themed during the v3 rewrite. It ships in Spanish and English.

Deployed as a GitHub Pages site (`juansbg.github.io`).

## Current state: a v3 rewrite is underway

The project is being rebuilt. The roadmap is six sprints; **all six are done.** v3 is the live site at the root; the old trees are no longer deployed.

`src/engine/` is complete and at full narrator-script parity: every role that takes a night step is wired end to end, including the ones that used to be prompted and then ignored (see "Every night step is real" below). `src/i18n/` holds the Spanish and English string tables and the outcome renderer. 529 tests, no DOM, no strings in the engine. A simulator plays whole games against the engine and a balance test runs on every test run (see "The simulator" below). The app installs and runs offline (see "The app is a PWA" below). The UI lives in `src/ui/`: one token set in `tokens.css`, screens in `src/ui/screens/`, autosave in `store.ts`.

`STATE_VERSION` is 4. Version 1 saves did not track the Apothecary's vials, version 2 did not record the day's votes, and version 3 had no trades and no seed; `store.ts` migrates all three on load (`healUsed`/`poisonUsed` default to false, `votes` to empty, `trade` to null, one fresh `seed` shared by every snapshot) rather than dropping the game. Bump the version again only with a migration beside it.

### How the narrator's flow works now

- **Setup is names only.** `screens/setup.ts` starts with a single field: type a name, Enter, repeat. The player count is how many names were typed; there is no count picker. The list is remembered in `omerta:roster` across resets — reset forgets the game, not the people — and a separate "Clear the list" asks before wiping it.
- **Roles are dealt at random** (`engine/deal.ts`) by default; manual assignment stays as an override. A line under the complexity chips (`balanceMarkup` in `screens/setup.ts`, numbers from `engine/balance.ts`) says how many of the table will be Family and whether the table leans one way: `balanceOf()` plays 1,000 detective-led bot games per size and complexity, seeded and cached, and only claims a lean beyond two to one. Once roles are set by hand it counts the Family actually seated and drops the lean if that differs from the dealer's plan. The crew is `floor((n + 1) / 4)`, one at five or six players, two up to ten, three up to fourteen; the Godfather is dealt from `GODFATHER_FROM` (eight) players up. Both numbers came out of the simulator: rounding to nearest gave six players two crew, and one conversion then ended the game on the first morning half the time. The dealer only ever hands out roles the engine fully resolves — `NOT_AUTO_DEALT` lists the exceptions and a test enforces it. The list is now just `SPLIT` (the script gives the Cultist no win condition, so it is a pure manipulation card and a table must choose it) and `PICK_SIDE` (counts as crew for the deal but may stay with the town, so it would unbalance whichever side it does not pick). The Chameleon (`SWAP`) is dealt at complex tables since its card picker exists.
- **Citizens have a trade** (`Player.trade`, an index into the string tables' `trades`, `TRADE_COUNT` of them, the same order in both languages so the engine holds a number and never a word). `createGame` deals them to the `PLAIN` seats from a shuffle of its injected `Random`, unique within a game, and `assignTrades()` settles them again when the roles are (the `[data-deal]` tap that leaves setup): a seat dealt a role loses its trade, a citizen keeps theirs. A converted citizen keeps theirs too. The held card shows it under the role in a quieter line (`.reveal__trade`); nothing before the hold does, and the Detective reads the role, not the trade. The trade is the town's claim space and the paper's breadcrumb (`docs/GAZETTE.md`). `GameState.seed` is drawn at the same time for anything the engine rolls itself.
- **The dead are named for what they were, a day late** (`revealedDead()` in `engine/state.ts`): a death logged on night N is public from the morning of day N + 1, role, side and trade, always. It is the one rule that makes a role public, and the only way a role reaches the room: `TvProjection.revealed` carries exactly those players and the leak test allows exactly those ids. The paper's investigation articles read from it; nothing else may show a dead player's role before the game ends.
- **The paper gets a breadcrumb** (`rollClue` in `engine/resolve.ts`, at the end of `resolveNight`). At most one `clue` outcome a night, public, rolled from `GameState.seed` and the night (`engine/rng.ts`: mulberry32 and a mixer), so the Apothecary's dry run, an undo and a reload all roll the same. It names a living citizen's trade and never a seat: `neighbour` (someone from the Family lives next door, or nobody does, the Bloodhound's question asked of any seat via `crewNextDoor`) or `doors` (the distance round the circle to tonight's victim). Sixty percent of quiet nights, a quarter of nights with a death (`CLUE_CHANCE_*`). `renderOutcome` picks a line by night from a bank per kind (`outcome.clue`, `tradesNamed` supplies "the baker"); the accent is the town's and the reading marks it ¶. `balance.test.ts` checks every clue in three hundred simulated games against the state that produced it — **a clue that could be false is a bug, not flavour.**
- **Every night step is real.** Each of these was once a prompt whose answer went nowhere; the fix for each lives in `screens/night.ts` and `engine/resolve.ts`:
  - *The Godfather* (`CONVERT`) is asked after the Family has chosen, with the victim named and two buttons — take them in, or let the hit go ahead (`data-night-confirm` / `data-skip`). It used to offer only Confirm, so every prompted night converted. Once the one conversion is spent (`infectionUsed`) `scheduleFor` drops his step; he still wakes with the Family, there is just nothing to ask.
  - *The Associate* (`PICK_SIDE`) records a `chooseRole` to `KILLER` or `PLAIN` on night one (`data-choose-role`). A bare `confirm` was recorded before, which the resolver ignores.
  - *The Apothecary* (`MEDIC`) has one cure and one poison per game (`healUsed`, `poisonUsed` on `GameState`). The cure only unlocks on someone `doomedTonight()` says is about to die; the poison on anyone living. A cure poured on the living is not spent. When both are gone the step still appears with a note to wake her anyway, so the table learns nothing.
  - *The Chameleon* (`SWAP`) picks from `spareCards()` in `engine/cards.ts`: every town card nobody at the table holds, minus first-night-only cards (already inert by his step) and the plain Citizen. Taking one is a `chooseRole`; the table hears which card left the centre via a public `cardTaken` outcome and never who took it. The Veteran's free life travels with its card.
  - *The Cultist* (`SPLIT`) taps seats into the first faction, the rest form the second, and `data-split-confirm` stays locked until both have someone. The split is recorded on `Player.sect` and shown only to the Cultist; no win condition is implemented, by design.
  - *The Renegade* (`ROGUE`) may target his own side — only `KILLER` is kept off the crew in `legalTargets`.
  - *The Family's hit* is scheduled while anyone who wakes with the Family is alive (`scheduleFor` adds `KILLER` for any living crew member except an unjoined Associate). It used to need a living plain member, so a Family of just the Godfather and the Renegade slept through the rest of the game.
- **The night table is safe to turn around by default.** At every night step the circle is rendered through the acting role's perspective (`perspectiveFor()` in `screens/night.ts`): no role labels, sigils, team colours or question flags, only what that role already knows, and still tappable for the narrator. A Roles toggle in the night header (`data-peek`) brings the narrator's full board back for that step only and resets on every move. Show renders `playerViewMarkup`, the same perspective as a full screen with no controls and no bar, for holding up across the table. What each role sees is decided in one place, `perspectiveFor()`. The Family sees the whole Family in one red with no "you" mark, so nothing singles out which red seat is the Godfather or the Renegade. The Godfather also sees the Family's pick. The Apothecary sees who is set to die and which vials she has left. The Chameleon sees the centre; the Cultist sees both factions as they form. Everyone else sees a plain table and their own seat. `circleMarkup` takes a `perspective` option for this and ignores every narrator-facing option when it is set. The leak tests in `night.test.ts` ("the player's view") check both languages — **do not weaken them**, and route any new per-role knowledge through `perspectiveFor`, never through the markup directly.
- **The seating circle is the target picker** (`screens/circle.ts`). Seats render as `data-seat` / `data-target` / `data-lynch` depending on the question, so the existing handlers pick them up. Ineligible players are dimmed and disabled, never hidden; the crew glows red for the narrator (v2's idea). **The ring never draws a tile under 3.5rem**: `fitTables()` (`screens/circle.ts`, run by `app.ts` after every paint and on resize) mirrors the CSS seat algebra and flips the circle to rows (`[data-rows]`) when the room cannot give every seat a readable tile, so a short phone, a two-line morning report, the Apothecary's step or twelve seats all get full-width rows that scroll instead of a shrunken ring. The list layout in ⋯ is the same rows, chosen on purpose (`list` on `circleMarkup`; `listMarkup` is gone). The Apothecary's vials sit inside her card under the prompt, not in a row of their own.
- **Outcomes are coloured cards** (`screens/timeline.ts`, `outcomeCardMarkup`): the morning report, the log, and the end-of-game history all colour each entry by the role that caused it via `i18n/outcomeAccent`. This is v1's `displayCards` rebuilt on structured outcomes. The page ground tints cold at night and warm by day (`html[data-phase]`).
- **The dawn slideshow** (`screens/dawn.ts`) is the morning report as a performance: it starts by itself when the night ends (after the Gunman's shot, if he died) and ▶ on the day screen replays it. Each public outcome is a full screen, a death on a Vendetta ground with Midnight ink and a line from a per-cause bank in the string tables (`ui.dawn.death`, ten lines per cause per language, each its own small story). `deathLines()` walks the whole log and gives each death its seat's own pick or the next free one, so nobody in a game is read a sentence someone else already got, and undoing the latest death moves nobody else's line. **The town's verdict is read the same way:** `verdictSlides()` opens full screen as soon as the town has voted (after the Gunman's shot, if they hanged him), under the `ui.dawn.verdict` heading; `dawnKind` in `app.ts` says which reading is up. Tonight's log is split at the first execution, so replaying the morning after a vote does not include the vote. Both readings are built from the same public outcomes as the report, hide the bar while open, and close only through their own Done.
- **The table view turns the screen to the whole room** (`screens/table.ts`, the "Show the table" row in ⋯, the `tableView` flag in `app.ts`). It renders a `TvProjection` (`src/room/projections.ts`) and nothing else: names, who is dead, silenced and marked, the count against each seat and the leader, the clock by day, and the current reading as a card over the table, with the reading's own controls since it is the narrator's device. The projection is plain JSON built from public facts only and is what a TV will receive through the relay later (`docs/BIG-SCREEN.md`); `projections.test.ts` asserts it carries no role, no secret outcome and no voter — **do not weaken it**, and add any new public fact there rather than reaching into `GameState` from the view. The bar is not rendered while the table view is up. It is designed for a phone or an iPad on its side, so the manifest no longer locks the orientation.
- **The screen opens the room and the narrator joins it by code** (`docs/BIG-SCREEN.md` §11; user, 2026-09-12: the old flow, where the phone opened the room, showed the players' QR on the one device that holds every role, and the TV came last by a typed address with a fragment, was "super clunky"). A TV opens the site's `/tv` (GitHub Pages serves it without the `.html`; `screenUrl`) and asks the relay for a room with no key (`requestRoom`, `POST /rooms` with an empty body); the room is unclaimed, a code and a fifteen-minute alarm, and screens and players may join it before any narrator. The names screen carries the code field (`ScreenJoin` on `namesMarkup`: five letters submit by themselves once a key is stored; the key field sits under it the first time and again after a refusal; the TV's address in the hint is a link a TV pointed at the root can follow) and the phone claims the room with the key (`claimRoom`, `POST /rooms/:code/claim` with `X-Room-Key`; a claim with the key always wins, the replaced narrator's socket is closed 4000). With a room the names screen shows one line (`.room-line`: the screen, the screens on, the phones seated) and the door reads "Everyone is in"; **the narrator's phone never shows a QR** on that path. The relay keeps each phone's last join and hands them to the narrator's socket in `present` (`players: { cid, name, pub }[]`), so a phone that scanned before the narrator arrived is admitted at once. A socket on a room that does not exist or has expired is accepted and closed with 4004 (`gone()`), since a refused upgrade is indistinguishable from the relay being down in a browser. The ⋯ "Big screen" sheet is settings (the relay address, the key) and the no-TV road: "Open a room from this phone" opens and claims in one call as before and turns the phone to the lobby with the QR, since there is nothing else to show it on. `/tv` and `/seat` are on the service worker's `navigateFallbackDenylist`.
- **The room says what it is doing** (`docs/BIG-SCREEN.md` §12, after ten critics played whole evenings in September 2026). The relay tells every screen and phone whether a narrator is on the room (`{kind: 'narrator', here}`), sent on connect and on every change, so a TV whose narrator has gone waits out loud and stops by itself when one returns; a socket that dies without a goodbye arrives as an error rather than a close, so both roads tell the room. Closing the room is a decision, not a disconnection: the narrator sends `{kind: 'end'}`, the relay drops the room and closes every socket with 4001, and a screen says the evening is over instead of hunting for a code. A narrator replaced by a second phone with the key gets its own final status (`replaced`) and says so, rather than showing a reconnection that will never happen. A guest whose phone leaves is marked `gone` rather than forgotten, so the seat is held against the **name** and the same person on a borrowed handset lands back in it. What a phone says while no narrator is attached is kept (the last twenty messages) and handed to the next narrator socket after `present`. The seat projection carries the `roster` while the table fills up and a `reading` flag while the narrator reads, and the phone holds the night ground and a "the town is waking up" page until the room has heard the morning — the dawn belongs to everyone at once, not to whoever looks down first. `TvProjection.nightStep` is two plain numbers off the schedule (never a role, never a seat) so the big screen can say the table is deciding and how far through the night it is.
- **A TV can follow the phone** (`src/room/client.ts`, `relay/`, `tv.html` + `src/tv.ts`, the "Big screen" row in ⋯). The phone keeps one WebSocket up as the narrator (`NarratorLink`, reconnecting with backoff, one message per frame at most). `render()` ends with `publish()`, so the TV receives the same `TvProjection` the table view renders after every paint; the clock travels as a deadline and the TV counts down by itself. The room sheet shows the code, how many screens are on, and the address a second screen joins at (`tvUrl`: the code in the fragment, never in a query). The room is saved in `omerta:room` so a reload reconnects; "Close the room" forgets it. The relay address defaults to `VITE_RELAY_URL` at build time and can be overridden on the sheet (`omerta:relay`). `tv.html` is a second Vite entry: it joins as a screen (`ScreenLink`), renders `tableMarkup(projection, false)` and nothing else, and never loads the narrator's handlers.
- **Before the game, the big screen is a lobby** (`lobbyMarkup` in `screens/table.ts`, `join` and `roster` on the projection, setup only). It shows the room code, the players' QR and the roster filling up, each name marked once a phone holds it; on the narrator's own device it carries "Everyone is in" (`data-table-proceed`), which turns the names into the roster and lands on the deal. Opening a room during setup turns the phone to the lobby at once, since a stood-up phone or a mirrored iPad is the screen the table looks at. **A room's table is whoever joins it**: opening a room with no game yet, booting with one open, and restarting inside one all empty the names list (the remembered roster is for an evening without phones; in a lobby it would show as players nobody can find), and a restart re-keys the room (`rekeyRoom`: forget the guests, a fresh hello) so every phone joins again by name. The lobby's button is disabled with the minimum-players line until four names are at the table. A TV gets there by address (shown on the room sheet), not by scanning: the sheet carries the players' QR only, plus the seated names. **A bare `tv.html` opens the room itself** (`src/tv.ts`, §11.5): it asks the relay for one (`requestRoom`), keeps it in `omerta:screen` so a reload lands back on it, connects as a screen and paints the lobby at once from what it knows, before any projection: `lobbyMarkup` takes a `Lobby` (`code`, `join`, `roster`, an optional `note`), and `roster: null` is the third state, no narrator yet, where the roster's column carries one eyebrow and one line for the narrator ("Open The Family on your phone and enter this code") and the relay's state under it; the claim's first projection fills that column and nothing on the left moves. `LinkStatus` has a final `gone` (`NO_SUCH_ROOM`, the relay's 4004): a screen that opened its own room asks for a fresh one, a second screen that joined by fragment says there is no room at the address, and a player's phone goes back to the code field with "That room has closed". **A bare `seat.html` asks for the code** (`codeMarkup` in `screens/seat.ts`): five characters set like the code on the screen, uppercased as typed; submitting sets the fragment and reloads, so everything keyed by room starts clean.
- **Players join from their own phones** (`seat.html` + `src/seat.ts`, the second QR on the room sheet, `seatUrl`). One address for the whole table: a player scans it, types a name, and the phone gives them a seat by name — while the roster is still names, a matching name takes that seat and a new name is added to the list; once the game has players, only a matching unclaimed name will do, and a stranger is refused until the narrator seats them by hand. Each player's page keeps a connection id and an ECDH key pair in `sessionStorage`; the phone makes its own pair per page load, says `hello` with the public half on every fresh socket, and seals every seat projection with the shared AES-GCM key (`src/room/crypto.ts`), so the relay never holds a role in the clear. `seatProjection()` carries exactly one role, the seat's own, and only once the cards are dealt (`dealt` = the narrator has left setup); its leak test allows nothing else. A seat with a phone is skipped by the pass-around (`revealOrder`), so a table that all joined never passes the narrator's phone. Votes from phones go through `castVote`/`withdrawVote` with the same `'vote'` timeline entry as the narrator's taps, after the same checks. **The ballot is sealed**: the room sees how many have voted, and whose hand is up (`TvSeat.voted`), never for whom, until the narrator taps Reveal on the day head; then the count comes up one ballot at a time (`countOrder`/`countUp` in `screens/vote.ts`: rounds across the seats pointed at, fewest first, so the last ballots all fall on the leader), at a beat the narrator's phone keeps (`shown` and `COUNT_BEAT_MS` in `app.ts`, published as `TvProjection.count` with the partial `tally`, the `leader` only once complete; sealed again by `leaveDay()`). The table view puts the figure and the verdict in the middle of the ring (`circleMarkup`'s `centre`), and the phone gets the same count on its own ring. The narrator's own screen always shows the full count. **The night comes from the phones too** (`docs/BIG-SCREEN.md` §10, user 2026-09-11): `SeatProjection.tonight` (`seatNight()` in `projections.ts`, null by day and before the deal) is the step being read (public, the narrator says it), whether this seat acts at it (`actsAt` in `src/room/actions.ts`: its own role's step, or the Family's for anyone who wakes with the Family), `perspectiveFor()` as data with `self` pinned to the one seat and the dead given a plain night, the seats it may pick (`eligibleAt`, the engine's `legalTargets`), and what its card holds and nothing else: the Apothecary's vials and, at her step alone, the doomed; the Godfather's conversion and the Family's recorded pick; the centre on the Chameleon's phone at his step; the card the Detective looked at, on his, for the rest of the night. `SeatProjection.players` (id, name, alive) is there so the phone can draw the ring. A phone sends `mark` (the Family's shared proposal: it sets the narrator's `picked`, which every Family phone sees as `view.marked`) and `act` (a `SeatAction`, the tap the narrator would have made); the relay checks shapes and forwards both with the socket's `cid`; `acceptAction()` on the narrator's device is the gate (the sender acts at the current step, the target is legal, the vials and the centre hold what is asked, the split leaves someone on both sides, the Associate may only choose a side) and what passes is recorded through `mutate` as an `'action'` entry like a tap, so undo and the log cover it; what fails is dropped and the phone is sent its unchanged step. The narrator still reads the night and nothing advances on a timer: when every seat a step wakes holds a phone the night card says they are choosing on their phones (`ui.night.onPhones`, the `phones` argument of `nightMarkup`) and the seats stay tappable underneath, so a seat without a phone, or a dead battery, plays as today. `playthrough.test.ts` (`checkSeatNight`) holds every seat's block to this at every step of 150 games and allows exactly four role ids on a phone: its own, the step, the Chameleon's centre, the Detective's look — **add to it on purpose, never by loosening a check**.
- **The night is played from the phones too** (`docs/BIG-SCREEN.md` §10; the phone's half is `screens/seat.ts` and `seat.ts`, the contract and the narrator's gate are the room's). While the phase is night the seat projection carries `tonight`: the step being read (public, the narrator says it aloud), whether this seat is acting, `perspectiveFor()` as data, the eligible seats, and the role's own knowledge (the vials, the Family's pick, the centre, the Detective's look). `seatMarkup` shows every phone the same screen at every step — the night, the step's role and sigil, the plain ring through `tonight.view`, the hold shrunk to a bar — and gives the acting phone alone the chooser, mirroring `night.ts` step for step: a seat then Confirm (each tap also sends a `mark`, the Family's shared pick that any Family phone may move and any may confirm), two seats for the pair, a seat then a vial for the Apothecary with the vials locked as hers are, the first faction then Confirm for the Cultist, the centre's cards or "Keep your card" for the Chameleon, take them in or let the hit go for the Godfather, the two sides for the Associate. A tap becomes an `act` through `seatAction()`; the phone marks it sent and dims the row, and **never assumes it landed**: the narrator's next projection either moves the step on or brings it back unchanged (`settlePicks` in `screens/seat.ts`: a player step's pick is dropped for the narrator's mark, the pair's, the potion's and the split's picks stay until sent or the step changes). **The chooser sits behind a gate** (`nextGate`, `SeatGate` in `screens/seat.ts`; user, 2026-09-11): when a step becomes the seat's, the phone shows only "[Name], it's your turn" and one button (`data-enter`), the chooser comes on the tap, and once the step is done (by this phone, another Family phone or the narrator) it shows "Close your eyes, [Name]" and one button (`data-close`), the Detective's looked card as a dark page first; the gate pages are the common screen with one sentence changed and the button where the hold bar sits, and the ring between steps is plain on every phone, the Family's included, so eyes that opened early read nothing off a neighbour's phone. A step that is the seat's again at once skips the closing page. The dead see the night like everyone else. A screen wake lock is asked for once a projection is up and again when the page comes back to the front, so no phone goes dark mid-night. `seat.test.ts` covers each step kind from hand-built projections, and `playthrough.test.ts` allows on a phone exactly the step's role name, the Chameleon's centre and the Detective's look, and no other role.
- **Every screen is checked over whole simulated games** (`src/room/playthrough.test.ts`): the bots play 150 games and, after every single state change (`playGame`'s `watch`), the test builds the TV projection and every seat's projection, renders `tableMarkup`, `seatMarkup` (`screens/seat.ts`, the player page's markup kept out of the entry for this) and the held card, and checks that a phone carries exactly its own role, that the room carries none but the paper's revealed dead and the card the Chameleon took, that votes and eligibility match the engine, and that no reading names a living player's role. What it deliberately allows: the faction's name (the Family is public), the cause of a death by role (poison, the shot, heartbreak), the winner line at the end, and a convert's own trade on their own card. Add any new public fact to its allow-list on purpose, never by loosening a check.
- **The relay is public and metered, so it keeps three doors shut** (`relay/src/index.ts`, top). Only requests whose `Origin` is in `ALLOWED_ORIGINS` (`[vars]` in `relay/wrangler.toml`, the site; `"*"` in the uncommitted `relay/.dev.vars`) are answered at all; being a room's narrator needs the `ROOM_KEY` secret (`npx wrangler secret put ROOM_KEY -c relay/wrangler.toml`, typed once into the code field or the Big screen sheet, kept in `omerta:roomKey`, sent as `X-Room-Key` on a claim or a phone-opened room; a screen needs none to open a room); and one address gets thirty handshakes or openings a minute through the `RATE` rate-limiting binding. A room holds at most forty sockets. The account stays on the Workers Free plan, which refuses requests past its daily allowance rather than billing them; do not add a payment method or upgrade until release.
- **The relay is one Cloudflare Worker and one Durable Object per room** (`relay/src/index.ts`, `relay/wrangler.toml`, its own `relay/tsconfig.json`). It stores the secret's hash, the last projection per target and nothing else; forwards votes and joins to the narrator; refuses a wrong secret, a message over 16 KB or more than twenty a second; and deletes itself after six idle hours. `npm run relay:dev` runs it locally with no account (Miniflare, port 8787), `npm run relay:check` typechecks it, `npm run relay:deploy` needs `npx wrangler login` once on the machine. The smoke test is a Node script against a running relay: open a room, connect narrator, TV and seat, check fan-out, replay on connect, a vote arriving as the socket's own seat, and that a TV cannot publish. The protocol is in `docs/BIG-SCREEN.md` §4–5.
- **The day table is plain by default too.** After the slideshow the phone may be facing the town, so `dayMarkup` shows names, who is dead and who has a question, and nothing else. The same Roles toggle as the night (`data-peek`, the `peeking` flag in `app.ts`) brings roles and the crew glow back for the narrator, and every move resets it.
- **The discussion has a clock.** `screens/timer.ts` is a pure model (a length, and either a wall-clock deadline or the seconds left) plus the clock row `dayMarkup` paints under the day head: one wide face, tap to start, tap to pause, a tap on a finished clock starts it over, and ↺ beside it. The length (1, 2, 3 or 5 minutes) is a segmented row in ⋯ during play. `app.ts` owns the only interval: it repaints the digits in place through `data-timer-digits` rather than re-rendering every second, and at zero it parks the clock, buzzes, and repaints once, unless a role card is being held. The whole timer is saved to `omerta:timer` (`loadTimer`/`saveTimer`), so the PWA reloading itself mid-argument loses nothing; a new morning, a vote, the next night, a rewind and a restart reset the count, never the length. The row lives in the day markup only, so the slideshow, the shot and the reveal never show it.
- **The vote is recorded from the day screen, two taps at a time.** A Votes word button beside the execution question (`data-voting`, the `voting`/`voter` flags in `app.ts`) swaps the seats from `data-lynch` to `data-vote`: tap the voter, then their pick; the voter again takes it back. Each tap goes through `mutate()` as a `'vote'` timeline entry, so undo and the log cover it, and the mode stays on for the next voter. `screens/vote.ts` holds the pure parts: `voteChoices` (voters first, with the dead and the silenced dimmed; every living seat once a voter is armed), `voteCounts`, and `tallyMarkup`, the count as a row of names under the question. Counts also sit on the seats as `.seat__votes` badges (a `votes` option on `circleMarkup`) and `leader()` marks the seat the town points at with `data-leader`; nothing executes but the narrator's own tap. Everything leaving the day (`leaveDay()`) turns the mode off. The row is inside `dayMarkup`, so a slide, the shot or a reveal never shows it.
- **The town gets a paper every morning.** `screens/paper.ts` is one newspaper in three editions (`docs/GAZETTE.md` is the design). `edition(state, day, locale)` sets the day's public outcomes as articles in page order: deaths by name (a headline from the bank for its cause in `ui.paper.headline`, handed out by `deathLines()` like the dawn lines so no two deaths in a game share one, and the dek is the very line the town was read at dawn), the verdict with the count if a tally was recorded, the public events (the fire, the mark, the growl, a card taken; a bank each, picked by night) with the report line as the dek, the investigations, and zero to two colour pieces. **The investigation rule** is `revealedBy()`: a player who died on night N or day N is named for what they were (role and side) in the edition of day N + 1, always and only then; it is a view over the log, not an outcome. **Colour never names a trade, a person or a role** (`ui.paper.colour`, sixty pieces per language, picked by a stride so a game never reads one twice; `paper.test.ts` holds every paper bank clear of the trades with the same word-prefix regex `i18n.test.ts` uses on the death lines, and the colour and the clue headlines clear of the role names too — keep it that way, a colour piece that reads as a clue is a lie). A quiet night with no colour scheduled still gets one piece. The investigation names a citizen's trade too (`tradesNamed`), the first time the town hears it. A `clue` outcome is an article after the investigations, under a headline that only says somebody talked; its line is the engine's, nameless by construction. `editionOf()` takes a projection-shaped source (`day`, `players` as id and name, the public `log`, `revealed`), so the phone and a TV set the same page: `tableMarkup` renders it without controls while `TvProjection.paper` names an open edition, and `revealed` is the engine's cumulative `revealedDead`, which the edition filters to the deaths of the day before. `dailyMarkup(edition, locale, controls)` is the full screen. On the phone the morning reading ends on it (`endReading()` in `app.ts` opens it when the last slide closes; the verdict reading does not) and the Morning word button on the day head (`data-dawn-play`) replays the reading, which lands on it again (`paperOpen`); it has its own Done, the bar is not rendered while it is up, and anything that leaves the day drops it.
- **The game ends on the final edition.** `paperOf()` is the pure data (the winner as the banner, every public death as an article with the night as its eyebrow and the very line `deathLines()` gave it at dawn as its dek, who was who with the Family and the dead marked, the record night by night from `renderOutcome`), `paperMarkup()` is the page on the game-over screen, and `paperImage()` draws the same page onto a 1080px canvas. `sharePaper()` hands that PNG to the Web Share API where the browser can share files (`canShare({files})` first); where it cannot, the image comes back as an object URL and `app.ts` shows it in a sheet (`paperShot`, `shotMarkup()`) for a long press, since a download link in an iOS standalone window goes nowhere obvious; `unavailable` means no canvas at all, and the screen says a screenshot will do. The old coloured history cards and the compact circle are gone from that screen; the paper carries both.
- **History is persisted**, capped at `HISTORY_LIMIT` moves (`store.ts`), so the log and every "rewind to here" survive a reload. Setup edits are kept for rewinding but hidden from the log (`kind: 'setup'`).
- **Every finished game goes into the record** (`engine/summary.ts`, `omerta:stats` in `store.ts`). `summarise(state, endedAt)` folds a game whose `winner()` is settled into a `GameSummary`: the seed, the winner, the nights, every seat by name with its role, side, trade, whether it stood at the end, how and when it died, and whether it was on the winning side (`won`: the team's win, the pair's, or the martyr's own), plus the Detective's looks and hits measured against the cards at the end. It is null while the game is on. `render()` writes it through `recordGame()` the first time it paints the game-over screen (`recordedGame` holds the seed so a repaint does not write again; leaving the screen arms it again, so an undo past the end and a different last day replace the earlier ending, since a game is known by its seed). `loadStats()` is the list, oldest first, capped at `STATS_LIMIT`; a restart keeps it like the roster. `aggregate(games)` is the pure roll-up the statistics screen renders: a `TableStats` line (games, wins by side, nights, looks and hits) and one `NameStats` row per person matched by `nameKey` (trimmed, case-folded, the same match the lobby uses), most games first. **The ledger is the screen** (`screens/stats.ts`, `statsMarkup(games, locale)`, the Statistics row in ⋯, the `statsOpen` flag in `app.ts`): a full screen in the timeline's voice on the dark ground, the table's line (wins by side, nights a game, the Detective's hits over looks; a side that never won and a Detective that never looked are left out) over one row per name with its figures (wins by side carry their share), tonight's names list first in its own order and then everyone the record remembers most games first, the list scrolling inside the screen. It has its own Done, the bar stays since no player sees it, and "Clear the ledger" at the end of the list asks on the confirm sheet (`Pending` `'clearStats'`) before `clearStats()`.

### Sound and haptics

- **Three cues, no files.** `src/ui/sound.ts` synthesises everything with the Web Audio API: the night is filtered noise with a drifting cutoff over two detuned 55 Hz sines (`sound.night(on)`, called from `render()` so it follows the screen and fades over a couple of seconds), the verdict is one drum (`sound.drum()` in the lynch handler: a sine falling 150→45 Hz over a noise burst), and a chosen seat, a vote or the shot is a 25 ms tick (`sound.tick()`). Nothing is fetched or precached. Browsers refuse audio outside a gesture, so `unlockOnGesture()` opens the context on the first tap, starts any night that was asked for before it (a game resumed from a save), and resumes it on later taps after iOS has suspended it. The ambience keeps playing while the phone is turned to a player: wind tells nobody anything, unlike the bar.
- **Sound is off by default** (user, 2026-09-11): only a stored `on` under `omerta:sound` makes a sound; a fresh install, a test run and a dev tab are silent until the narrator turns it on in ⋯. **The mute is a row in ⋯** (`data-mute`, `sound.setMuted`), stored under `omerta:sound` by the module itself, not in `store.ts`. Muted, no context is ever created. `createSound(make)` takes the context factory so `sound.test.ts` drives it with a fake.
- **Haptics are `buzz()` in `dom.ts`**: a 12 ms tap on most moves, a three-beat pattern on the verdict and when the clock runs out. It returns early under `prefers-reduced-motion`, which is the only switch it has; the sound mute does not cover it.

### Layout and chrome rules

- **The page never scrolls.** `html/body/#app` are a fixed `100dvh` with overflow hidden; `#app` is a two-row grid of `.stage` over a persistent `.bar`. Only designated regions scroll: the morning report, the timeline sheet, the end-of-game history, the names list. The seating circle is sized from `min(width, height)` of its container so it shrinks on short phones. A change that makes `document.documentElement.scrollHeight > innerHeight` on any screen at 375×667 is a regression.
- **One bottom bar, one menu.** Timeline is the only first-class button; everything else (language, circle/list, show a role again, end the game, restart) lives behind ⋯. Per-screen primary actions stay in the stage. **The bar is not rendered while a player can see the screen** — during a reveal, while the phone is turned to a player (`showingPlayer`), while a dawn slide is up, or while the day's paper is open — because the timeline would show them every move and the menu can end the game. Each of those is an early return in `chromeMarkup()`; they are independent and order does not matter. Do not add loose buttons to the bottom of screens.
- **Entrances play once.** `screen-in`, `seat-in`, `card-in` and `line-in` only run when the stage carries `data-enter`, which `render(true)` sets for an animated `setState` (a step, a screen, a move). `setState({}, false)` repaints the same scene without them, so a pick, the menu or a toggle never bounces the table into place again. A new entrance keyframe on stage content goes into the `.stage:not([data-enter])` list in `styles.css`; sheets and dawn slides are deliberately not in it.
- **The day's vote is recorded, optionally.** `castVote` / `withdrawVote` keep one vote per voter on `GameState.votes` (the dead and the silenced cannot vote, nobody votes for themselves, a stale tap is ignored), `tally()` counts them most-votes-first with the Raven's extra, and `leader()` names the top seat or null on a tie. `lynch()` writes the votes to the log as a public `tally` outcome ahead of the death and clears them; nightfall clears them too. The narrator may still just tap the name, in which case nothing is recorded. The dawn split (`tonight()` in `dawn.ts`) cuts at the tally, so it opens the verdict reading and stays out of the morning replay.
- **A wipe-out is the town's win.** `winner()` no longer returns `null` when nobody is alive: every road there runs through the last crew member dying (the Gunman hanged with two left and shooting the other), and the crew-count check answers it. The `null` left the app on a day screen with an empty table.
- **Who a role may target is the engine's rule**, `legalTargets` in `engine/targets.ts`; the night screen re-exports it, and the simulator's bots pick from it, so the two cannot disagree.
- **Seats can be rearranged only during setup** (`swapSeats` / `moveSeat` in `engine/state.ts`). Ids are seating positions and are referenced from the log and lovers once play starts, so both refuse after that.
- **Destructive actions ask on our own sheet.** Clear names, end the game and restart open `confirmMarkup()` (`app.ts`, the `confirming` flag): the question in body type, Cancel, and a Vendetta button carrying the same label as the row that was tapped. They used to be `window.confirm`, which flashes a white system dialog in a dark room. Add a fourth destructive action by extending `Pending`, not by calling `window.confirm`.

### The app is a PWA

- `vite-plugin-pwa` (`vite.config.ts`) generates `sw.js` and `manifest.webmanifest` at build time and injects the manifest link; `src/main.ts` registers the worker. Everything the build emits is precached (`globPatterns` includes fonts and icons), so a complete game runs with no network. `registerType: 'autoUpdate'` means a new deploy takes over silently and reloads the page: the game is in `localStorage`, so nothing is lost, but the local flags (`showingPlayer`, `picked`, the reveal phase) reset to the narrator's side, which is the safe side.
- The worker's scope is the site root. The app lived at `/beta/` until the cutover on 2026-09-02, so `public/beta/` carries a redirect page and a `sw.js` that installs over the beta's worker, clears its caches, unregisters and sends open windows to `/`. Keep both until every phone that installed the beta has opened it once more; the root worker ignores `/beta/` (`globIgnores`, `navigateFallbackDenylist`). A saved game survives the move: `localStorage` is per origin, not per path.
- Icons are `public/icon-*.png`, rasterised from `favicon.svg` with `rsvg-convert`; the maskable one is the same fedora on a padded viewBox so it survives the platform's mask. Regenerate all three if the sigil changes.
- An install row appears in ⋯ only while the browser has fired `beforeinstallprompt` (Android/desktop Chrome). iOS has no such event; there the user adds to the home screen from Safari's share sheet, and `apple-touch-icon.png` is what it shows.
- **Verifying offline:** the in-app browser pane refuses to fetch service-worker scripts, so it cannot prove this. Build, `npx vite preview`, and drive headless Chrome over the DevTools protocol instead: register, wait for `activated`, `Network.emulateNetworkConditions {offline: true}`, navigate, and assert `#app .stage` rendered and the fonts loaded. `src/vite-env.d.ts` carries the plugin's types for `virtual:pwa-register`.

### The simulator

- `src/engine/sim/` plays whole games through the public engine API with crude bots (`policies.ts`: everyone picks a legal target at random; the town votes at random, by following the Detective, or by following the Detective and reading the paper — `clueVote` believes every living citizen's trade claim and reads each `neighbour` breadcrumb against the seating of its own night, `aliveAfter`; the gap between `detective` and `clues` is what the breadcrumbs are worth, measured in `docs/ROADMAP.md` §1). `playGame` is the loop, `stats.ts` the summary, `report.ts` the table. `npm run sim [games]` prints it (bundled with rolldown by `scripts/sim.mjs`, since Node cannot run the extensionless TS imports directly); paste the result over the table in `docs/ROADMAP.md` after any change to the dealer, the resolver or the win conditions.
- `balance.test.ts` runs 400 games per setting, every size from 5 to 15 at every complexity under all three policies, and fails on a stall, a game with no winner, more than 1% wipe-outs, more than 5% of games over before the first vote, or either side winning less than 15% of detective-led games. The bounds are loose on purpose: the bots play badly by design, and the test exists to catch a rule change that decides the game, not to tune it. **The win rates it prints are indicative, not a measurement of the real game.**
- The bots sit out `SPLIT` and `PICK_SIDE`, which the dealer never hands out. A new role with a night step needs a case in `randomNight` only if its action is not a plain target.

### Design language

**`docs/DESIGN.md` is the authority for anything visual.** Read it before touching `src/ui/`. The short version:

- **Five colours, named, and nothing else.** Vendetta `#FF0F0F` (blood, the crew, anything lethal), Midnight `#000029` (the ground), Ash `#D8D4C0` (secondary ink, hairlines, the town; and, a shade dimmer, the newsprint of the town's paper), Ledger `#F7F6F2` (primary ink; the one bright surface, used for the morning report and the held role card), Neon `#54F4FF` (the role glyphs on dark grounds, and nothing else: never text, a button, a surface or a side; Midnight on paper). Every other value in `tokens.css` is a `color-mix()` of these. Never add a sixth, however neutral it looks.
- **Three faces, self-hosted.** Bebas Neue for anything that is a label (titles, buttons, seat names, the marks), IBM Plex Sans for anything read aloud, IBM Plex Mono for numbers. They come from `@fontsource` packages imported in `src/main.ts`, never a CDN.
- **Radius is zero everywhere.** The `--radius-*` tokens resolve to `0`. Depth is a hairline and a surface step, not a shadow.
- **Colour is keyed by side, not by role.** Markup carries `data-accent="crew|town|occult|system"` from `src/ui/accent.ts`; the role's identity is its sigil from `src/ui/sigils.ts` (straight lines on a 24 grid, judged on `docs/sigils.html`), drawn in Neon on dark grounds and Midnight on paper. There are no per-role hues.
- **Two contrast traps:** text on a Vendetta button is Midnight, never white; red on paper is a rule or a strike-through, never small text.
- **The held role card and the inspect card carry no team colour.** The glow of a phone across a table must not say which side.

`docs/design-language.html` is the same spec rendered as a page, with live components.

### Traps worth knowing

- **Nothing may reach `setState` during module evaluation.** `connectRoom()` used to run at the top level, `NarratorLink.connect()` reports its status synchronously, and that handler repaints — so it touched `setState` two hundred lines before the `const` declaring it, threw, and stopped the module. A narrator who reloaded with a room open came back to a blank screen with the saved game still in storage and no way to reach it. The room is joined after the first paint now, and `onStatus` returns early until `painted` is true. The trap had been there for weeks and only fired once a repaint became unconditional: a latent ordering bug is invisible until something downstream stops being guarded.
- **A broadcast loop must guard every `send`.** `ctx.getWebSockets(tag)` hands back sockets that may already be closing, and `send()` on one throws — which, inside a `for`, means every socket after it silently gets nothing. One stale phone in a room stopped the whole room being told the narrator had arrived, and four of those killed the worker. `relay/src/fanout.ts` guards and prunes; `tell()` returns how many actually heard, and `tellNarrator` holds a message when nobody *heard* it rather than when the list was empty — a list of sockets is not a listener. The test that catches this closes the FIRST socket and asserts the last still receives; closing the last one passes on the broken code.
- **A death is `public: true` by construction** (`engine/types.ts`), not by convention, which is why a dead seat's public-only log holds every death in the game and `deathLines()` run on a phone reproduces the narrator's assignment exactly. Anything relying on that should say so, because it is a guarantee from the type rather than from two call sites agreeing.

- `doomedTonight()` (`engine/resolve.ts`) is a dry run: it calls `resolveNight` on the pending actions so far and reads the direct victims off the outcomes. That is only safe because `resolveNight` is pure. If the resolver ever gains a side effect, the Apothecary's step will trigger it twice.
- `NarratorLink.publish` collects paints on a 16 ms timer, not `requestAnimationFrame`: a hidden page never gets a frame, so an rAF-gated publish left the room stale whenever the narrator's tab was in the background (found with the browser pane hidden: the roster reached the TV only when a screenshot forced a paint). Keep any coalescing on the room's links off rAF.
- **A scrolling region measured mid-paint keeps a lie all morning.** The regions are measured inside the paint that builds them, and what they hold is still arriving: a seven-player day table measured 220px against a 208px floor at 45ms and 208 against 208 at 106, so it wore a "more below" fade over nothing — and kept it, because a region is only re-read on a paint, a resize or a scroll, and a narrator reading the report does none of the three. Re-read after the scene settles.
- **Nothing that crosses the edge of the stage is visible to the page-scroll numbers or to the overflow check**: the stage hides its own overflow, so a clipped column reads as `{0,0}` and an empty overflow list. `.claude/audit.js` grows an `offEdge` list for exactly this, and it is the only thing that catches it.
- `dom.ts`'s `swap()` must always run its callback. `document.startViewTransition` rejects when the tab is hidden or a transition is in flight; an unhandled rejection there means the screen silently stops updating. It now falls back to a plain paint.
- `createGame` draws trades and a seed from the system's randomness, and the seed decides whether the paper drops a breadcrumb on a night. A test that asserts what a quiet morning says (an exact report, one dawn slide, a record with two lines) must build its game with `quietGame()` from `engine/testing.ts`, whose seed never rolls a clue, or it fails one run in three. A test that only counts deaths or names is fine with `createGame`.
- Node 26 ships an experimental `localStorage` global that is `undefined` without `--localstorage-file` and shadows jsdom's. Tests that touch storage install a small in-memory shim (`store.test.ts`) rather than relying on either.

### The role reveal

`src/ui/screens/reveal.ts` is a pass-the-phone onboarding flow: handoff → confirm identity → **press-and-hold** to see the role. The hold is the security model, not decoration. A tap-to-reveal screen can be left face-up, handed over still showing, or screenshotted; a held reveal cannot outlive the hand holding it. `pointercancel`, `pointerleave` and `visibilitychange` all hide it, and the language/reset chrome is removed while a role is on screen. `reveal.test.ts` asserts no role name or team appears in the handoff or confirm markup, in either language — **do not weaken those tests.**

The same screen serves the mid-game "show a role again" flow in `single` mode, selected by player id from a picker.

The held card carries the brief and nothing longer. A citizen's trade is its second line, right under the role and in the same Bebas at `--text-xl` (`.reveal__trade`): "CITIZEN" over "BAKER" is what a player must walk away knowing, so it is never a quiet footnote. A "How it plays" section with the role's fuller `detail` used to sit under the brief; it was cut off on short phones and the user had it removed. The `detail` string stays for the narrator, who reads it to a player who flagged a question. `reveal.test.ts` checks that the card has the brief and the trade in that order and does not carry the detail.

Two rules the whole design rests on:

1. **The engine never produces a user-visible string.** It emits structured outcomes (`{type: 'kill', roleId: 'LOB', targetId: 3, blockedBy: 'PRO'}`) and the UI renders sentences at display time. v1 could never be translated because it stored rendered Spanish fragments on each event and *rewrote them mid-resolution* (`"Ha muerto "` → `"Han intentado matar a "`) to signal a blocked kill — the sentence was carrying game state.
2. **`GameState` is JSON-serializable.** Autosave and undo both fall out of this for free.

Role identity is a **function-based ID** — `KILLER`, `INSPECT`, `GUARD`, `MEDIC`, `CONVERT` — defined once in `src/engine/roles.ts`. IDs name what a role *does*, never what it is *called*, so a re-skin costs nothing but a string table. Teams are `town` and `crew`.

This is deliberate and was learned the hard way: the IDs were Spanish werewolf acronyms (`LOB`, `VID`, `BRU`) until the theme changed to organised crime and every one of them became a lie. **Never reintroduce a theme word into an ID, a team name, or a death cause.** `roles.test.ts` enforces the shape.

## Why v1 is being replaced (verified, not theoretical)

Reproduced live on the deployed site:

- **Duplicate names silently corrupt the game.** v1 matches players by display name (`legacy/v1/script.js:191`, `:309`). With two players called "Ana", killing one marks *both* dead and drops `VID` from `rollsUsed`, so the narrator is never prompted for the Vidente again — with no error and no visible sign.
- **No viewport meta**, so `window.innerWidth` is 980 on a 375px phone and the whole page is scaled down. Everything is sized in `vw` against that 980px.
- **The Bruja's choice is discarded every night** — the Curar/Matar dropdown is populated but `configureLastStep()` has no `BRU` case.
- **`fillOptionsByRoll()`'s self-exclusion is dead code** — the `else if` re-adds every non-wolf the first branch excluded, so the Vidente appears in its own target list.
- `steps` is `{}` on night 1 but `[]` later, so `steps.length` in `prevStep()` is `undefined` on the first night.
- `prevStep()` unconditionally `events.pop()`s, deleting an unrelated event when stepping back past a role that recorded none.

These are the specification for what v3's engine tests must prevent, not bugs to go fix in `legacy/`.

## Reading v1 as the specification

`legacy/v1/script.js` is the most complete statement of the game rules that exists in code, so it is worth reading before writing engine logic — but read it as a draft spec, not as a reference implementation.

- `rollOrderFirstNight` / `rollOrderNight` (`:40-41`) are the night order. `calculateNight()` filters them to roles still alive.
- `prepararInforme()` is where rules actually resolve — protection, wolf kills, the Anciano's one-time survival.
- `event.show` marks whether an action is public knowledge in the morning report; secret actions (Vidente, Protector) are recorded but not displayed. v3 keeps this distinction.

**The authority is the PDF, not v1.** `Pueblo_duerme_Guion_DOS.pdf` in the repo root is the narrator script and wins any disagreement. It is untracked and gitignored deliberately: keep it local, and don't copy its prose into the app's copy.

### Rules the PDF specifies that no old code implements

These are Sprint 1 work, and the reason full parity is a goal:

- **Night parity** — Pirómano acts only on odd nights, Lobo albino only on even nights, Actor only the first three. v1 prompts all of them every night.
- **Roles that are selectable but do nothing** — Infecto converting its victim into a wolf, Cupido pairing lovers, Domador de Osos' growl, Cazador's revenge shot, Ángel, Niña Pequeña.
- **Abominable Sectario** — in the script, in neither old tree. `SPLIT` in `src/engine/roles.ts`; the split itself is recorded and shown to the Cultist, and nothing beyond what the script says is invented.

## Product goals and the decisions already made

Four goals drive v3. The decisions below are settled — don't relitigate them without the user.

**Ship as an installable phone app.** An offline PWA, not an App Store build (Capacitor stays possible later without rework, since it wraps the same build). Mobile is the primary target, not a responsive afterthought. Two consequences: nothing may depend on a CDN, and `GameState` must persist — a reload or a phone call currently ends the game.

**Fully playable in English.** Handled by the engine-emits-no-strings rule above. Role display names come from `src/i18n/` name packs.

**Independent role names.** The user's call, to keep the game free to play without brushing against another publisher's branding. Worth knowing the actual risk shape so it isn't over-applied: game *rules and mechanics* are not copyrightable, and short functional names ("Seer", "Witch") are ordinary descriptive words. The real exposure is trademark on *game titles* and copyright on *rulebook prose and art*. So the things that matter are the app's own name and not copying the PDF's wording — not the role names, which are cheap to make distinctive anyway since they live in a string table. (Not legal advice.)

**Modern UI with real motion.** The old trees are 2021/2022 Bootstrap pages with hand-rolled hex, `!important` overrides, and essentially no transitions. Constraints for v3:

- **One palette.** The old trees have two different colour sets for the same roles (`legacy/v1/script.js:43-62` vs `legacy/v2/game.js:11-25`). Establish one design-token set in Sprint 3; do not add a third.
- **All colour lives in CSS**, driven by a class or `data-` attribute. v1 writes `style.backgroundColor` inline from JS on every state change, which is exactly why it can have neither transitions nor a dark mode.
- **Don't port `LightenDarkenColor()`** (`legacy/v1/tools.js`) — its per-channel hex maths overflows into the next channel on bright colours. `color-mix()` replaces it.
- **The player circle comes from v2**, not v1. v2's is pure CSS custom properties (`legacy/v2/styles.css:29-56`) and survives rotation and resize; v1's computes `transform` in JS from `offsetWidth` at creation time and does not.
- **Dark-room ergonomics are a hard constraint.** This app is used one-handed, in the dark, by someone reading aloud. Dark-first palette, no white flashes, large touch targets, fast legible transitions over decorative ones, and honour `prefers-reduced-motion`.
- **Sizing is `clamp()` and container queries**, not `vw` everywhere — the old approach breaks on tablet and desktop.
